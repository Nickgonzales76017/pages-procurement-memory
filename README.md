# Procurement Memory and Acquisition Brief Studio

Two Aurekai experiences for teams that make buying, supplier and acquisition decisions.

**[Open Acquisition Brief Studio](https://nickgonzales76017.github.io/pages-procurement-memory/brief-studio/)**  
**[Open Procurement Memory](https://nickgonzales76017.github.io/pages-procurement-memory/)**

## Acquisition Brief Studio

Use this workspace to turn an opportunity into a concise, reviewable buyer brief.

1. Choose **Equipment acquisition**, **Property acquisition**, or **Supplier procurement**. The starting scenarios use illustrative source claims rather than confirmed inventory or a real property listing.
2. Select an opportunity, change the recipient and add the information your team has received. Link the original source where possible.
3. Review the decision-critical questions. You can add new checks, mark a source as supplied or record a local review. Those states do not claim independent verification.
4. Compare possible verification methods and set a budget. A remote walkthrough, a field technician and a qualified title specialist answer different questions. Two tasks done by the same provider on one trip can share travel cost.
5. Write the recommendation, turn brief sections on or off, change their order and inspect the recipient preview.
6. **Save workspace** keeps your draft in this browser. **Export brief** downloads a readable Markdown brief. **Export typed handoff** downloads a YAFF proposal for operator review. **Print** opens the browser's print flow.

The studio supports up to 16 requirements and 15 route options for each opportunity. You can bring up to 100 opportunities in one TSV import. The columns are `title`, `subject`, `source` and `assertion`.

The included examples show an equipment buyer considering unverified desktops and laptops, a Dallas property research scenario, and a proposed supplier. They are not offers from the named organizations, accepted quotes, verified title findings or instructions to contact anyone.

### What does it cost to verify?

An estimated route includes labor, any fixed charge and travel. When the same provider covers multiple checks during one visit, travel is counted once. The planner shows both fully covered and incomplete options so you can decide which additional questions merit expense.

A route shown as **Quoted** or **Recorded ready** has only the references entered into the workspace. This standalone browser demo does not independently contact providers or validate those assertions. Paid inspection booking and institutional evidence review remain separate authorized operations.

### Where does my draft go?

Drafts are saved locally in your browser using structured-clone storage. No source data or draft is sent to a vendor, customer or Bonfÿre service when you edit, compare or save it. Clearing this browser's site data may remove it. Export a copy if you need to take the work elsewhere.

The typed handoff is a proposal for review; exporting it does not create a mission, send a message, reserve a technician, authorize payment or change a live property record.

## Procurement Memory

The original <https://nickgonzales76017.github.io/pages-procurement-memory/> application provides file preparation and a GitHub-native intake pathway for vendor calls, contracts and procurement records. It remains available independently from Brief Studio.

The upload route requires an authorized GitHub account. Downloading an intake copy is a preparation step; actual processing depends on a successful GitHub commit and its pipeline. The page's pipeline labels are not proof that a user's file was processed.

## Connections to the wider Aurekai work

The broader ecosystem includes the [Aurekai Work Samples](https://aurekai-work-samples.pages.dev/), the [Dallas Council Media Workbench](https://nickgonzales76017.github.io/pages-town-box/civic-council/) and [Aurekai Work](https://aurekai.work/studio/). They serve different use cases and authority boundaries. The Council Media Workbench provides source-linked meeting records; Brief Studio can produce a recipient-specific proposal, while native Work handles governed follow-up.

For a customer implementation, the next step is to bind this interaction to the organization's existing source, provider, finance and WorkGraph owners. It must also connect authenticated saving, authoritative evidence and authorized effects. Those links are not asserted by the browser preview.
